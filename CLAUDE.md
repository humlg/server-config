# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A NixOS flake-based system configuration for a single home lab machine (flake output `nixosConfigurations.HomeLab`, `networking.hostName = "HomeLab"`). It is deployed via `nixos-rebuild --flake`, not built as an application.

## Commands

Applying changes (run on the target NixOS machine, as the `david` user, via shell aliases defined in `zsh.nix`/`userspace.nix`):

```sh
rebuild        # sudo nixos-rebuild switch --flake /home/david/repos/server-config#$(hostname)
rebuild-test   # sudo nixos-rebuild test   --flake /home/david/repos/server-config#$(hostname)
```

`$(hostname)` must match a `nixosConfigurations` attribute name in `flake.nix` (currently only `HomeLab`). Since the alias derives the target from the live hostname, this repo assumes it's being applied on a machine literally named `HomeLab`; running `rebuild` from a differently-named host will fail to find a matching flake output.

To just check the flake evaluates without switching:

```sh
nix flake check /home/david/repos/server-config
nixos-rebuild build --flake /home/david/repos/server-config#HomeLab
```

`nix.settings.experimental-features = [ "nix-command" "flakes" ]` is set in `configuration.nix` specifically so bare `nix` CLI calls (e.g. `nix flake update`) work — `nixos-rebuild --flake` enables these internally for its own use but that doesn't extend to other `nix` invocations run manually.

## Structure

- `flake.nix` — single entry point, pins `nixpkgs` to `nixos-25.11`, defines the `HomeLab` nixosSystem.
- `configuration.nix` — main system config (bootloader, networking, locale, users, base packages, SSH). Imports `hardware-configuration.nix` and `userspace.nix`.
- `hardware-configuration.nix` — machine-generated by `nixos-generate-config`; treat as read-only/regenerated, not hand-edited.
- `userspace.nix` — user-facing tooling (CLI packages like `fastfetch`, `lazygit`, `btop`; zsh setup). Imports `zsh.nix`.
- `zsh.nix` — zsh/oh-my-zsh config and shell aliases (`rebuild`, `rebuild-test`).
- `modules/` — one file per service/concern, imported from `configuration.nix`:
  - `storage.nix` — mounts the second disk at `/mnt/data` (media, downloads, and service state live there; root disk is small), shared `media` group, directory layout.
  - `vpn.nix` — WireGuard road-warrior server (`wg0`, remote access into the LAN) and the `vpn-confinement` egress namespace (`egress`) that Transmission's traffic is forced through.
  - `media.nix` — Jellyfin, Transmission (confined to the `egress` netns), Sonarr, Prowlarr, and the Homarr dashboard (container — no nixpkgs module exists for it).
  - `home-assistant.nix`, `minecraft.nix` — one service each.

Secrets (WireGuard private keys, the VPN provider's config, Homarr's
encryption key) are **not committed to git** — deployed out-of-band on
HomeLab itself to the paths referenced by `privateKeyFile` /
`wireguardConfigFile` / `environmentFiles` options in the modules above.

## Working with flakes

Nix flakes use the **git tree** as the source, not the working directory. This has two important consequences:

- **New files must be staged before evaluation.** Any file you create (e.g. a new module) is invisible to `nix flake check`, `nixos-rebuild build`, and all other flake-aware commands until it is at least staged with `git add`. The build will fail with `path '…' does not exist` otherwise. Always `git add` new files before running a flake check or rebuild.
- **Uncommitted changes to existing files are visible** once staged, even before committing — the dirty-tree warning (`warning: Git tree '…' is dirty`) is expected and harmless.

Workflow for adding a new module:

```sh
# 1. Write the file, add an import in configuration.nix
# 2. Stage both so the flake can see them
git add modules/new-module.nix configuration.nix
# 3. Verify evaluation before committing
nix flake check /home/david/repos/server-config
# 4. Commit
git commit …
```

## Notes

- This is a config-only repo with no build/test/lint tooling beyond Nix's own evaluation (`nix flake check`) — there is no app code to run.
- Per user instruction, changes in this repo should be committed automatically without being asked, but never pushed without explicit request.
